# goats-bot

Телеграм-бот бегового клуба. Два модуля в одном боте:

- **Лига челленджей** — участники каждый день присылают видеокружок в топик группы. Бот считает серии, месячный зачёт и рейтинги.
- **Тренировки** — админ создаёт занятие одной строкой, бот публикует пост, собирает участников опросом, напоминает и ведёт учёт приходов по скриншотам Стравы.

Одна установка обслуживает **несколько групп**: у каждой свой челлендж, свои судьи, свои тренировки и свои призы.

## Как это устроено

**Кружки и приходы засчитываются сразу.** Судья не подтверждает, а только отменяет зачёт — в любой момент, без ограничения по времени. Так человек не ждёт чужого решения, чтобы закрыть день, а модерация остаётся выборочной.

**День закрывается в полночь** (настраивается). Пропустил — серия обнуляется. Отмена зачёта уже после закрытия дня убирает кружок из месячного счёта, но серию не рвёт: переснять человек всё равно не мог.

**Серии считаются из истории**, а не хранятся как счётчик: поля в базе — кэш, источник истины — зачтённые дни. Поэтому поздняя отмена или возврат вердикта пересчитывают всё корректно.

## Стек

Python 3.12 · aiogram 3 · SQLAlchemy 2 (async) + aiosqlite · Alembic · APScheduler · pydantic-settings

Long polling, без Docker. Разворачивается как systemd-юнит.

## Архитектура

```
bot/
  handlers/       приём апдейтов, никакого SQL
  services/       бизнес-логика: зачёты, вердикты, серии, тренировки
  repositories/   запросы к БД
  db/             модели, сессия, типы
  middlewares/    сессия, пользователь, клуб, троттлинг
  keyboards/      инлайн-клавиатуры и CallbackData
  scheduler/      задачи по расписанию
  texts.py        все пользовательские тексты
migrations/       Alembic
tests/            179 тестов
```

Правило: SQL живёт в `repositories`, логика — в `services`, хендлеры только принимают и отвечают. Все тексты — в `texts.py`, чтобы правки формулировок не расползались по коду.

### Мультиклубность

`Club` — это группа со своими топиками, судьями, заданием и призами. На каждый апдейт middleware определяет клуб по `chat_id` и подменяет объект настроек его клубной копией (`settings_for_club`). Благодаря этому сервисы и планировщик не знают о клубах вовсе: они по-прежнему спрашивают у настроек «куда постить» и «кто судья», просто ответ теперь зависит от группы.

Задачи по расписанию оборачиваются в `per_club` и проходят по всем активным клубам; падение одного не роняет остальные.

## Запуск

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env      # заполнить BOT_TOKEN и id чатов
.venv/bin/alembic upgrade head
.venv/bin/python -m bot
```

У @BotFather для группы нужно **отключить privacy mode** (`/setprivacy` → Disable) или сделать бота админом — иначе он не увидит кружки.

### Добавить ещё одну группу

Отправить в ней `/newclub` — в том топике, куда будут присылать кружки. Дальше `/setclub` задаёт задание, призы и остальные топики.

Пока группа не заведена, бот в ней молчит.

## Тесты

```bash
.venv/bin/python -m pytest -q
```

Покрыты вещи, которые ломаются молча: границы суток и часовые пояса, анти-чит, гонка двух судей за один вердикт, поздняя отмена зачёта, изоляция клубов друг от друга, расписание задач.
